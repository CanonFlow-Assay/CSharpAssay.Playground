03 / Run verification locally
Reproduce it with the actual tool.
Install the exact repository SDK first. Follow the canonical engine local-feed guide rather than installing an unpublished native version from NuGet. Dependency restore can require network access; the verifier itself does not need an AI provider.
  1. Prepare and install matching local analyzer/tool packages.
  2. From the Playground root, prepare qualified packages from the matching clean qualified engine checkout.
  3. Run the actual ExpenseGuard gate with Docker/PostgreSQL available. Missing database execution is a failure, not a skipped success.


./eng/prepare-assay.sh ../CSharpAssay --qualified-bootstrap-locks
./eng/tooling packed-assay -- explain CSAI0001
export ASSAY_RUNNER="$PWD/../CSharpAssay/src/CsAssay.Runner/bin/Release/net11.0/cs-assay.dll"
./eng/run-expenseguard.sh --output "$PWD/evidence/generated/expenseguard/first-run"
Use a fresh disposable checkout/output directory. The engine checkout must contain its completed qualification; preparation records local consumer-lock changes. Artifact paths include qualification.json, verify.json, verify.sarif, verify.html and verify.md.
