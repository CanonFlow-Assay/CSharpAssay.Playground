# Application-independent DAA undertaking

Owner authorization: 22 October 2026. Work and review use local Forgejo only;
existing GitHub branches and PRs must not be updated by this undertaking.

Requirements registered before implementation:

1. Preserve the exact .NET 11 toolchain, seven admitted rules and all evidence
   minima. Diagnose engine latency without raising its 50 ms budget or changing
   the representative workload. Retain failed experiments and qualify packages
   from the exact clean source commit.
2. Accept declared worker scenario identities, check identities, trace contracts
   and requirement-bound probes. No fetch-specific counts, schema or command
   selection may remain in the generic application coordinator. An explicit
   legacy adapter can preserve previously generated v0.1 starter manifests.
3. A v0.2 manifest requires acceptance criteria mapped to executed named tests.
   Missing/duplicate observations, unknown probe kinds, source escapes and stale
   artifacts cannot produce ReadyForReview or inference eligibility.
4. The second application is an HTTP inventory reservation API with immutable
   native outcomes and a PostgreSQL effect adapter. Required behaviors: stock
   conservation under concurrency; request-key idempotency; conflict detection;
   atomic stock/reservation/outbox commit; rollback on injected failure;
   cancellation; public wire-contract compatibility. Requirements and exact
   acceptance tests precede implementation. Local database credentials are
   generated in memory, never printed or committed.
5. Execute a new maximum-per-request requirement through plan, failing tests,
   implementation and baseline-preserving candidate verification. Then introduce
   a real wire-name regression that existing behavior tests miss. ContractAssay
   must fail and DAA must select an eligible contract investigation. Invalid and
   stale proposals must not obtain execution authority. Compare with the visible
   deterministic baseline; do not infer provider quality or human approval.

Completion requires real engine, worker, test, contract, mutation and decision
artifacts. A passing sample is not independent human review, production-load
qualification, a new admitted rule, or a waiver of engine release failures.
